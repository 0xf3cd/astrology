Chart results and text¶

简体中文 · Chart · API

natal_chart returns an immutable NatalChart in memory. Inspect its structured values or pass it to format_chart with an explicit knowledge catalog. The package provides no chart save/restore API or storage schema; see the release notes for the API removal.

A complete example¶

This synthetic record falls in the half-hour repeated when clocks move back on Lord Howe Island. Choose the earlier occurrence with fold=0. The location is specified separately, not inferred from the timezone. There are no default aspect orbs.

>>> from datetime import date, time
>>> from astrology import (AspectRule, BirthRecord, Body, ChartConfig, HouseSystem,
...   IanaTimezone, Location, LunarNode, MajorAspect, ObjectOrb, OrbCombination,
...   TimePrecision, format_chart, load_catalog, natal_chart, prepare_natal_input)
>>> record = BirthRecord(date(2026, 4, 5), time(1, 45), IanaTimezone("Australia/Lord_Howe"),
...   Location(0, 0), TimePrecision.MINUTE, {"record": "synthetic"})
>>> config = ChartConfig(HouseSystem.WHOLE_SIGN, (*Body, LunarNode.MEAN_ASCENDING),
...   tuple(AspectRule(a, 6, (ObjectOrb(Body.SUN, 10),)) for a in MajorAspect),
...   aspect_objects=tuple(reversed(tuple(Body))), orb_combination=OrbCombination.MEAN_OF_ORBS)
>>> chart = natal_chart(prepare_natal_input(record, fold=0), config)
>>> chart.resolved.utc.isoformat()
'2026-04-04T14:45:00+00:00'
>>> len(chart.positions), bool(chart.aspects), sorted({h.orb_limit_deg for h in chart.aspects})
(11, True, [6.0, 8.0])
>>> catalog = load_catalog()
>>> table = format_chart(chart, catalog)
>>> print("\n".join(table.splitlines()[7:10]))
Sun [sun] | Aries 14°50'21" | 9 | D
Moon [moon] | Scorpio 13°32'41" | 4 | D
Mercury [mercury] | Pisces 17°05'04" | 8 | D

The Sun’s orb is 10° and the other bodies use 6°. Taking the mean gives a limit of 8° for pairs involving the Sun and 6° for other pairs. aspect_objects excludes the node and lists the bodies in reverse order; participants in the result still follow the order in objects.

The full table includes all requested objects, four axes, twelve cusps, aspects with their oriented branches, deviations, limits and motion labels, requested/effective configuration and provenance. English is the default; pass language="zh-CN" for Chinese output. The supplied catalog must contain current names in that language; missing or ambiguous names fail rather than fall back to another language. Loading the catalog is explicit; formatting itself performs no resource I/O.

Read the structured result¶

  • resolved.record keeps the original Gregorian date, clock, stated precision, timezone form, location and source metadata. resolved separately keeps UTC, the offset, IANA key, fold and both timezone-data versions.

  • requested keeps object/rule order, per-object orbs, their combination and the distinction between omitted (None) and explicit aspect participants. effective.aspect_objects gives bodies/nodes in requested order, then explicitly selected axes in ASC/MC/DSC/IC order.

  • positions keeps unrounded longitude/latitude in degrees, physical distance in AU and longitude rate in degrees per TT day. Nodes have no distance (None). times keeps JD(UT1) and JDE(TT). houses keeps the four axis longitudes and twelve cusps in degrees; placements gives signs and house membership. Every aspect keeps its branch, signed deviation, limit and motion status.

  • provenance keeps astrology/celestial-calendar versions, position frame and UT1 derivation; effective keeps the resolved Delta-T model and evaluation.

Constructing NatalChart directly checks field types, ranges, and whether signs, house membership and aspects agree with the supplied positions, axes, cusps and rules. See the validation boundary for what these checks establish. Use natal_chart to calculate values from resolved input.

Selected axis names in participants, orb overrides and hits come from the supplied catalog, just like body names. An old body/node-only request needs no axis concepts: the existing four axis-geometry row labels remain fixed bilingual labels.

Calling natal_chart(chart.resolved, chart.requested) calculates a fresh result with the current implementation and records its provenance. It keeps the resolved birth input without looking up the timezone again. The new result may differ from an older result calculated with different code. The distribution must be installed: missing celestial-astrology metadata raises importlib.metadata.PackageNotFoundError rather than inventing a version. A version label alone does not identify a unique source revision or guarantee bitwise equality between trees.

Display does not change classification¶

format_chart angles use the named truncate_display rule: truncate toward zero to whole arcseconds. Aries 29.9999999° displays as Aries 29°59’59”, not Taurus 0°00’00”. House and aspect-motion labels come from the unrounded result. An object’s displayed longitude can match a cusp’s while its unrounded position is still in the preceding house; a nonzero deviation displayed as zero can still be applying or separating. In the positions table’s last column, R means decreasing object longitude, D means increasing longitude and S means exactly zero rate, all judged from the unrounded rate.

Formatted tables are for reading, not lossless interchange or restoration of the source charts. The lunar-phase and house-ruler formatters instead show their stored degree floats, as described in their guides.

Verification and limits¶

Tests compare results from the source checkout and installed package to check that packaging has not changed them. Separate tests check numerical agreement with Swiss Ephemeris data and changes from historical samples. These tests cover a limited set of cases and do not guarantee accuracy over the full supported range. The contributing guide records the test data, conventions, tolerances (including model differences and treatment near cusps), and redistribution limits.
