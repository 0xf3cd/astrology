Traditional rulership, dignities and dispositor chains¶

简体中文 · API · Knowledge

sign_ruler and essential_dignities use the rules recorded in William Lilly’s Christian Astrology (London, 1647), for Sun, Moon, Mercury, Venus, Mars, Jupiter and Saturn, the seven classical planets in traditional astrology.

The assessments belong to traditional essential dignities and debilities. This API assesses only four sign-level statuses: domicile, exaltation, detriment and fall.

rule.lilly1647.essential_dignities identifies this fixed rule set in the implementation, HouseRulers.rule_id and the knowledge catalog. It does not load or select rules dynamically.

Query a sign without a chart¶

Use sign_ruler to look up a sign’s traditional ruler, or essential_dignities to check the four statuses for a body in a sign. For example, Mars rules Scorpio; Mercury is both in domicile and exaltation in Virgo, and in detriment and fall in Pisces:

>>> from astrology import Body, Sign, DignityStatus, sign_ruler, essential_dignities
>>> sign_ruler(Sign.SCORPIO) is Body.MARS
True
>>> essential_dignities(Body.MERCURY, Sign.VIRGO)
(<DignityStatus.DOMICILE: 'domicile'>, <DignityStatus.EXALTATION: 'exaltation'>)
>>> essential_dignities(Body.MERCURY, Sign.PISCES)
(<DignityStatus.DETRIMENT: 'detriment'>, <DignityStatus.FALL: 'fall'>)
>>> essential_dignities(Body.SUN, Sign.TAURUS)
()

Every match is returned, in domicile, exaltation, detriment, fall order. Domicile means a planet occupies one of its own zodiacal houses (its ruled signs), not a numbered chart house. Exaltation applies throughout the assigned sign. Detriment is opposite a domicile; fall is opposite exaltation. See the generated twelve-sign table.

An empty tuple means none of these four. It does not establish peregrine status, since other dignities are not assessed. Strings, nodes and unrelated enums raise TypeError; use exact Body and Sign members. Valid outer-planet bodies (URANUS, NEPTUNE, PLUTO) raise ValueError naming the unsupported body, rather than returning an empty assessment. Scorpio uses Mars, Aquarius Saturn and Pisces Jupiter; there is no modern co-ruler substitution.

Follow the rulers in an existing chart¶

Calculate this synthetic example once, then read its existing cusps and placements:

>>> from datetime import date, time, timedelta
>>> from astrology import (BirthRecord, FixedOffset, Location, ChartConfig, HouseSystem,
...     natal_chart, prepare_natal_input, HouseRulers, format_house_rulers, load_catalog)
>>> chart = natal_chart(prepare_natal_input(BirthRecord(date(2000, 1, 1), time(12),
...     FixedOffset(timedelta(0)), Location(0, 0))),
...     ChartConfig(HouseSystem.WHOLE_SIGN, (Body.SUN, Body.MERCURY), ()))
>>> result = HouseRulers(chart)
>>> result.chart is chart, len(result.houses), result.rule_id
(True, 12, 'rule.lilly1647.essential_dignities')
>>> first = result.houses[0]
>>> first.house, first.cusp_sign.value, first.ruler.value, first.placement, first.statuses
(1, 'aries', 'mars', None, None)
>>> third = result.houses[2]
>>> third.ruler.value, third.placement is chart.placements[1], third.statuses
('mercury', True, ())
>>> catalog = load_catalog()
>>> text = format_house_rulers(result, catalog)
>>> print("\n".join(text.splitlines()[:5]))
House rulers (Lilly 1647)
House system: Whole Sign
Rule: rule.lilly1647.essential_dignities
House | Cusp sign | Ruler | Ruler placement | Statuses
1 | Aries | Mars | Not calculated | Not calculated
>>> print(text.splitlines()[6])
3 | Gemini | Mercury | Capricorn 1.889...° / House 10 | None of these four

HouseRulers retains only the supplied NatalChart. Each houses access builds twelve new records in house order; repeated accesses return equal tuples. It uses actual cusp longitudes, not ASC or MC as replacements for the first or tenth cusp. Repeated cusp signs remain separate records. The requested house system and raw astronomy are unchanged. No ruler is recalculated or added to the chart; present placements are the original objects.

placement=None and statuses=None mean that the ruler was not calculated. An available placement with statuses=() was assessed and matched none of the four. The formatter distinguishes these states and prints every simultaneous status. It displays the ruler’s sign, unrounded degree within sign and numbered house. Status assessment uses the sign alone, not the displayed degree.

Construct an individual record¶

>>> from astrology import HouseRuler, Placement
>>> placement = Placement(Body.MERCURY, Sign.VIRGO, 0, 6)
>>> record = HouseRuler(house=3, cusp_sign=Sign.GEMINI, placement=placement)
>>> record.ruler is Body.MERCURY, record.statuses == essential_dignities(Body.MERCURY, Sign.VIRGO)
(True, True)
>>> record.placement is placement
True

HouseRuler is immutable. Its ruler and statuses derive from its fields and cannot be supplied separately. The individual record takes a cusp sign; use HouseRulers(chart) to derive that sign from a chart’s numbered cusp. See the rulership API reference for field validation.

Formatting and errors¶

format_house_rulers requires a supplied Catalog and current names in en or zh-CN. Table delimiters and nonprinting characters in names are escaped. Unlike the chart and comparison tables, which truncate angles to whole arcseconds, the ruler’s degree within its sign is shown as the stored decimal float; the example above abbreviates its digits with .... Status assessment still uses the sign alone. See the text API reference for formatter errors.

Follow dispositor chains¶

A placement’s dispositor is the traditional ruler of its sign. Use chart_dispositors to follow that ruler’s placement and continue until the path reaches a self-loop, a cycle or a ruler absent from the chart.

This complete synthetic example calculates all ten bodies but selects only the Sun and Moon as starting objects:

>>> from datetime import date, time, timedelta
>>> from astrology import (BirthRecord, Body, ChartConfig, FixedOffset, HouseSystem,
...     Location, natal_chart, prepare_natal_input, chart_dispositors)
>>> birth = prepare_natal_input(BirthRecord(date(2000, 1, 1), time(12),
...     FixedOffset(timedelta(0)), Location(0, 0)))
>>> chart = natal_chart(birth, ChartConfig(HouseSystem.WHOLE_SIGN, tuple(Body), ()))
>>> paths = chart_dispositors(chart, objects=(Body.MOON, Body.SUN))
>>> paths.chart is chart, tuple(body.value for body in paths.objects)
(True, ('sun', 'moon'))
>>> tuple(body.value for body in paths.chains[Body.SUN])
('sun', 'saturn', 'venus', 'jupiter', 'mars')
>>> paths.edges[Body.MARS] is Body.SATURN
True
>>> tuple(tuple(body.value for body in cycle) for cycle in paths.cycles)
(('venus', 'jupiter', 'mars', 'saturn'),)
>>> paths.final_dispositors, dict(paths.missing_rulers)
((), {})

The Sun in Capricorn leads to Saturn, then Venus, Jupiter and Mars. Mars leads back to Saturn: edges includes that closing link, while chains[Body.SUN] stops before repeating Saturn. The Sun is a tail into the four-planet cycle, not a member of it. The Moon reaches the same cycle, so cycles lists it once. Saturn, Venus, Jupiter and Mars were not selected as roots, but their placements remain available for traversal.

Read the other endings as follows:

  • final_dispositors lists reached planets that rule their own signs. Their self-loop edges remain in edges. For a root that reaches such a planet, chains[root] lists that planet once.

  • A two-planet item in cycles is domicile-based mutual reception under this rule. Longer cycles, such as the example, are not labeled mutual reception.

  • missing_rulers[root] gives the absent next ruler for that root. The path ends at the last available object, and the edge to the absent ruler remains.

For example, a chart containing only this Sun cannot continue to Saturn:

>>> sparse = natal_chart(birth, ChartConfig(HouseSystem.WHOLE_SIGN, (Body.SUN,), ()))
>>> incomplete = chart_dispositors(sparse, objects=(Body.SUN,))
>>> incomplete.chains[Body.SUN], incomplete.missing_rulers[Body.SUN]
((<Body.SUN: 'sun'>,), <Body.SATURN: 'saturn'>)

No missing position is calculated. Only components reached from the selected roots appear; several roots may have different final dispositors or cycles. The plural final_dispositors does not assert a unique ruler of the whole chart.

Dispositors(chart, objects) constructs the same immutable result directly. Selections are copied and ordered by the chart’s placements, not argument order. edges keys, roots and final dispositors follow source-chart order. Each cycle preserves edge direction and starts with its earliest member in source order. The cycles are ordered by those first members in source order. All mappings are read-only; paths, cycles and endpoint lists are tuples.

Pass an explicit, nonempty sequence of available Body or LunarNode members. Outer bodies and named nodes can start a chain; their successors still use the seven classical sign rulers. Axes and cusps are not admitted as roots. Wrong chart types, non-sequences, strings and wrong identity types raise TypeError; empty, duplicate or unavailable roots raise ValueError. An unavailable root is an input error, distinct from a missing successor in a valid chain.

paths.rule_id is rule.project.dispositor_chains. The project rule defines traversal and result ordering over Lilly’s unchanged sign-ruler table. Its knowledge entry records the source boundary and the limits of domicile-based reception. It provides no scoring, interpretation or modern co-rulers, and has no dedicated formatter.

Source and limits¶

See the rule and generated table for the assignments and their derivation, and the source record for the edition, scan, transcription conventions and research limits. The catalog keeps source excerpts, credited Chinese translations and project explanations distinct.

The four-status query does not assess exact exaltation degrees, sect, node dignities, triplicity, bounds/terms, faces, reception, aggregate scores or interpretation. Day/night domicile labels are not extra conditions on the four sign queries.

Catalog status concepts have IDs dignity_status.<value> and no request-configuration link. entry.essential_dignities has complete query prerequisites but remains reference_only and not_assessed. Catalog retrieval does not evaluate a chart.
