Sign distributions and natal lunar phase¶

简体中文 · API · Knowledge

Use these APIs to count selected placements by sign element or modality, or to classify a supplied Sun/Moon pair by lunar phase.

Query signs and count an explicit population¶

Pass the placements you want to count to sign_distribution. The example counts Sun and Moon equally and prints all element and modality categories:

>>> from astrology import (Body, Element, Modality, Placement, Sign, element_of,
...     modality_of, sign_distribution, format_sign_distribution, load_catalog)
>>> element_of(Sign.ARIES) is Element.FIRE
True
>>> modality_of(Sign.CANCER) is Modality.CARDINAL
True
>>> placements = [Placement(Body.SUN, Sign.ARIES, 10, 1),
...               Placement(Body.MOON, Sign.CANCER, 10, 4)]
>>> result = sign_distribution(placements)
>>> placements.clear()
>>> result.objects, result.total
((<Body.SUN: 'sun'>, <Body.MOON: 'moon'>), 2)
>>> result.element_counts[Element.FIRE], result.element_proportions[Element.FIRE]
(1, 0.5)
>>> result.modality_counts[Modality.CARDINAL]
2
>>> catalog = load_catalog()
>>> print(format_sign_distribution(result, catalog))
Sign distribution (equal counts)
Counted objects: Sun [sun], Moon [moon]
Total / denominator: 2
Rule: rule.zodiac.elements, rule.zodiac.modalities
Category | Count / total | Proportion
Fire element | 1/2 | 50.00%
Earth element | 0/2 | 0.00%
Air element | 0/2 | 0.00%
Water element | 1/2 | 50.00%
Cardinal modality | 2/2 | 100.00%
Fixed modality | 0/2 | 0.00%
Mutable modality | 0/2 | 0.00%

Each selected object contributes one count. total gives the object count and is the denominator for every proportion. In this example, the Sun is in a fire sign and the Moon in a water sign, so each element has 50%. Both signs are cardinal, giving that modality 100%. Every category is shown, including zero counts. Percentages use two decimal places alongside the counts and total. No planet weights or dominant scores are assigned.

Supply a nonempty sequence of Placement records with distinct identities from a common source, such as one chart. Choosing a consistent source is your responsibility; see the validation boundary. SignDistribution copies them into an immutable tuple in input order; counts, proportions and total derive from that snapshot. element_of and modality_of take Sign members. See the summary API reference for validation errors.

Classification sources and the distinction from historical sign groups are described in knowledge.

Classify a supplied Sun/Moon pair¶

Supply Sun first and Moon second, in degrees at the same instant and with the same coordinate convention. The function measures from the Sun to the Moon in the direction of increasing longitude, returning that angle and its lunar phase type:

>>> from astrology import lunar_phase, format_lunar_phase
>>> phase = lunar_phase(sun_longitude_deg=350, moon_longitude_deg=10)
>>> phase.elongation_deg, phase.phase.value, phase.direction
(20.0, 'new_moon', 'waxing')
>>> print(format_lunar_phase(phase, catalog))
Lunar phase type: New Moon Type
Moon minus Sun (longitude, degrees): 20.0
Angular direction: waxing
Rule: rule.lunation.rudhyar1950
A type covers an interval, not an exact event; no illuminated fraction is calculated.
>>> lunar_phase(10, 350).direction, lunar_phase(0, 180).direction
('waning', 'turning')

The oriented difference is (Moon - Sun) mod 360, in degrees. Finite longitudes may exceed one turn; the calculation removes whole turns. Bare numbers carry no instant or coordinate convention, so the scalar function cannot detect a frame mismatch.

See the generated intervals and source discussion. Each type spans 45°. The project uses half-open intervals, including the start but not the end. An exact boundary belongs to the following type, with 360° wrapping to 0°. Angles within (0, 180) are waxing, those within (180, 360) are waning, and exactly 0° or 180° is turning. These boundary assignments and direction labels are defined by this project.

LunarPhaseResult is immutable. Type, direction and rule ID derive from its angle; direct construction requires [0, 360). New Moon Type at 20° is not an exact conjunction. No illuminated fraction, 3D phase angle, exact-event search or personality interpretation is calculated. Direction describes the arc, not a rate-based forecast.

Compose from an existing natal chart¶

First calculate a chart from synthetic data, then count selected objects with chart_sign_distribution and read its lunar phase with natal_lunar_phase. Those two functions read the chart’s existing positions and placements:

>>> from datetime import date, time, timedelta
>>> from astrology import (BirthRecord, FixedOffset, Location, ChartConfig, HouseSystem,
...     natal_chart, prepare_natal_input, chart_sign_distribution, natal_lunar_phase)
>>> record = BirthRecord(date(2000, 1, 1), time(12), FixedOffset(timedelta(0)), Location(0, 0))
>>> chart = natal_chart(prepare_natal_input(record),
...     ChartConfig(HouseSystem.WHOLE_SIGN, (Body.SUN, Body.MOON), ()))
>>> summary = chart_sign_distribution(chart, objects=(Body.MOON, Body.SUN))
>>> summary.objects == chart.requested.objects
True
>>> summary.total
2
>>> natal_lunar_phase(chart) == lunar_phase(chart.positions[0].longitude_deg,
...                                       chart.positions[1].longitude_deg)
True

objects must be a nonempty selection of distinct bodies/nodes already in the chart. Results follow source-chart order, not selection order. To count all requested objects, explicitly pass objects=chart.requested.objects. No unselected body, node or axis is added. Axes are not placements and are rejected even when explicitly selected for these statistics. natal_lunar_phase requires Sun and Moon; missing positions raise an error naming the absent identities rather than calculating them. Full error contracts are in the summary API reference.

Catalog entries remain reference_only, with stated prerequisites complete and chart applicability not_assessed. Verified source inspection does not make catalog lookup a chart evaluation.

Numerical angle and display¶

Inputs are converted to floats. The function calculates their difference using exact ratios of those binary values, avoiding subtraction overflow or placing an angle on the wrong side of a boundary. It usually returns the nearest float. If rounding would move an angle from one side onto a boundary, it uses the adjacent float on the correct side instead. For example, lunar_phase(5e-324, 0) returns 359.99999999999994, not 360° or a false exact conjunction. This is a numerical approximation, not an exact real angle. Equal rotations preserve the mathematical difference, but rotating floats may already round inputs; bitwise invariance is not promised.

The phase formatter prints the stored float without arcsecond truncation. Labels never come from rounded text. format_sign_distribution and format_lunar_phase require current catalog names in en or zh-CN; missing or stale names cause an error instead of a language fallback. Names’ table delimiters and nonprinting characters are escaped. See the text API reference for formatter errors.
