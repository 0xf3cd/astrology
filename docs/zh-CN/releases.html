发行说明¶

English · 文档 · 发行流程

0.4.0¶

本版增加定位星链和移动对本命的精确行运命中，将 celestial-calendar 升至 1.1.1，并删除独立目录版本。 包索引：PyPI。

精确行运命中与 UTC 输入¶

transit_hits在显式现代 UTC 区间内搜索移动对固定本命的精确主要相位。 TransitHits 保留源盘、选择、TT 区间、实际模型及每次原生命中的速率和方向， 包括逆行重复命中与相切。不要求移动侧出生记录或地点；固定时刻行运盘、容许度窗口及返照不在本操作范围内。

依赖与平台¶

运行依赖精确钉住 celestial-calendar==1.1.1 和 tzdata==2026.5。 天文依赖提供行运搜索使用的 UTC 转换接口。 macOS arm64 下限从 14 升至 15；其他平台下限及 Python 3.11–3.14 支持不变。 已有本命计算和文本格式不变。

定位星链与守护关系归属¶

chart_dispositors(chart, objects=...) 返回不可变的 Dispositors，包含守护边、各选定根的路径、已到达的循环及最终定位星， 以及缺失的后继守护星。使用不变的 Lilly 传统星座守护表；遍历由项目定义，不提供评分或解读。

HouseRuler 和 HouseRulers 从 astrology.summaries 移至 astrology.dignities。 直接从模块导入的代码须更新路径，旧模块不留别名。 包根导入（from astrology import HouseRulers）仍有效。 这是一次 0.x 源码路径兼容性变化；命盘计算、尊贵归属及已有文本输出不变。

知识目录记录已核的 Meeus 交点项、相位及宫制的外部定义、修正后的 Lilly 扫描定位， 以及原件保留或访问限度。来源核查不改变命盘适用性或默认输出资格；模型选择、容许度及数值算法不变。

不兼容变化：删除目录版本¶

源码 API 删除 Catalog.version 及其构造参数。自定义目录改用 Catalog(concepts, variants, sources, entries)，省去原来的首个版本参数。 目录 JSON 的 version 键和发行清单的 corpus_version 键也已删除，不提供替代的独立目录版本。 若需查询已安装包的版本，使用 importlib.metadata 的 version("celestial-astrology")。 这是一次 0.x 兼容性变化；源码修订、文献版次及命盘来源信息仍保留。

0.3.0¶

此版本增加本命分析、四轴相位选择和双盘落宫功能。 包索引：PyPI。

  • 元素／模式分布：等权统计明确选择的对象，保留零计数类别、计数及比例。

  • 出生月相：按具名的 Rudhyar 规则及本项目说明的区间边界，对日月黄经角度分类。

  • 传统守护与尊贵状态：按 Lilly 的固定规则查询星座守护星、宫主星，以及入庙、擢升、失势和落陷。

  • 四轴相位：本命及静态双盘查询可显式选择上升点、中天、下降点和天底。 缺少的轴速率仍表示为缺失，不补成零。

  • 双盘落宫和双语比较文本：保留两张源盘，区分左右对象和接收对象的宫位。

此前源码快照中的 SVG 功能已删除。命盘计算、结构化结果和双语文本输出仍可使用。

指南按首次使用、具体 API 用法及验证细节分层。发行检查除了源码文字，还检查包描述和生成的双语页面。 发行流程区分自动保护和维护者验收，并说明如何在发布部分失败后补齐交付而不替换已发布文件。

天文模型、Python／平台支持和运行依赖钉版与 0.2.0 相同。 本版不增加行运、返照、构造关系盘或交互式排盘界面。

0.2.0¶

静态双盘交叉相位¶

cross_chart_aspects 用显式规则比较两张内存本命盘结果。CrossAspectHit 记录静态几何并区分左右端点， CrossChartAspects 保留双侧完整来源及比较请求。允许同名对象和交点间跨盘配对， 不设运动字段，也不转换共同历元。见双盘指南。

Ashmand 1822 年版星座分组¶

ashmand_sign_group 将已有 Sign 归入一个 AshmandSignGroup：至点、分点、固定或双体星座。 十二星座的完整分组表、历史命名说明、原文摘录和中文译文见知识指南。

不兼容变化：撤回命盘持久化¶

此版本删除了 dumps_chart、loads_chart、recompute_chart、ChartRecordError、 ChartReplayError 及 astrology.serialization 模块。命盘保存格式与历史记录兼容政策一并撤回， 不提供替代格式或兼容壳，包不再读取已保存的命盘 JSON。应用若仍需旧 API，可保留已发布的 v0.1.0 环境；其标签和制品不变。

用 natal_chart 计算，直接使用内存中的不可变 NatalChart，用 format_chart 显示。 原始／已解析出生输入、请求／实际配置、天文原值、领域校验和计算来源保留。 这次删除不改变天文计算、时区政策或依赖钉版。

0.1.0¶

首版提供现代热带黄道、地心本命盘，以及可独立浏览的中英文知识目录。 安装分发包 celestial-astrology，Python 导入名仍是 astrology。

交付的 API¶

  • 不可变的原始出生记录、显式时区解释及最终计算时刻。未知时间或地点保留为缺失； 本命盘准备会拒绝不完整输入，不补正午或推测地点。

  • 太阳、月亮、行星位置、明确命名的月交点定义、四轴，以及 Whole Sign、Equal、Placidus 宫制。 请求的几何无定义时抛出 ChartDomainError，不改用另一宫制。

  • 热带星座、只按黄经判定的落宫，以及带明确容许度规则和局部入相／离相状态的五大相位。 该状态描述计算瞬间的运动，不预测之后是否形成精确相位。

  • 带版本的命盘记录、恢复、显式重算及中英文文本输出。存储结果分别保留天文原值、 请求／实际配置与计算来源。

  • 不排盘、不初始化原生天文库的概念、具名规则变体、别名和引用查询。 来源核验、前提状态、展示资格与命盘适用性分别记录；原引文、译文及本项目撰写的说明各自注明出处。

排盘、相位、v0.1.0 记录及知识指南定义本项目采用的约定和收录的语料范围。

安装与兼容¶

支持 Python 3.11–3.14。运行依赖精确固定为 celestial-calendar==0.8.0 和 tzdata==2026.5。 这保留了选定的模型和时区数据，但可能无法与要求其他版本的应用共同安装。 本版不升级到 celestial 0.9，也不放宽依赖范围。

安装需要兼容的上游天文轮子：具有对应 manylinux 支持的 Linux x86_64 或 aarch64、 macOS 14+ arm64，或 Windows amd64。天文依赖没有 sdist。 astrology wheel 的 any 平台标签不取消这项限制；仅查知识也需要同样的安装。

schema v1 的恢复不加载天文库，原样保留存储值和来源，包括历史 0.0.0 记录。 重算要求已安装的 astrology／celestial 版本及记录中的模型精确匹配。 能恢复历史记录，不表示能在 0.1.0 下重算；版本或模型不匹配会抛出 ChartReplayError。 详见 v0.1.0 记录指南。

验证与限制¶

完整质量工作流覆盖 Linux Python 3.11／3.14 及 macOS／Windows 3.14。 发行安装消费者在 Linux x86_64 3.11／3.12／3.13／3.14、Linux ARM64 3.14、 macOS ARM64 3.14 和 Windows amd64 3.14 上使用同一份保留的 wheel。 这七项检查安装和消费者行为，不代表对每个受支持的 Python／平台组合都运行了完整质量检查。 各次运行结果和制品摘要记在发行记录中，不能提前写成这些任务已经通过。

独立的 JPL Horizons 和 Swiss 参考案例使用明确约定及文档规定的容差。 正确性指南说明其覆盖范围及共享模型的限制。 恢复往返和同一 runner 上的源码／安装包对拍检查信息是否保留，不能代替外部参考， 也不承诺跨平台浮点结果逐位一致。

适配层即使只选择部分对象，也会计算固定的十四对象联合快照。 实际可计算范围是该快照的星历／时标范围与请求宫几何的交集；天文库支持的民用年份不能直接当作 更窄的命盘计算范围。详见排盘限制。 历史输入研究、恒星黄道、行运／返照、关系盘、额外对象、解读及星盘图形界面不在本版范围内。
